# 桌面启动失败修复与验证

2026-10-24 用户反馈点击桌面软件不能使用。10:13—10:16 的真实桌面日志显示：本机前后端已就绪，启动器仍因中文应用控制报错退出，展示错误页。

## 原因与改动

Windows PowerShell 5.1 的 `Start-Process` 将原生 4551 转为不含错误码和内部异常的 `InvalidOperationException`。此前只匹配英文完整消息；Explorer 使用中文环境时，识别失败。前轮仅检查了快捷方式目标与本机服务，没有覆盖这次真实双击路径，验收范围不足。

修复提交 `71e46ce`，比较基线 `3b1d3e3`：保留原生 4551 识别，增加完整中文及中英混合消息的严格匹配。只降级可选局域网网关，端口冲突、普通拒绝访问、配置错误和文件不存在继续报错。不更改系统应用控制策略；不替换被阻止的程序。

补丁位于桌面快捷方式原本调用的共享脚本中，下次启动会直接读取，无需重装或重新创建图标。局域网仍受 Caddy 的系统运行许可限制。

## 本轮证据

- 新增中英文回归在旧代码上实际失败；修复后桌面三个测试文件 **8 passed、0 skipped，69.11 秒**。
- 包括四种消息语言组合、嵌套异常，以及非 4551 不能被静默吞掉的反例。
- 中文 UI 语言及桌面相同的 `*>>` 全流重定向，运行独立数据、构建、端口和进程清单的真实本机启动流程。Caddy 实际被系统阻止后，启动流程成功，回环入口保留、LAN 地址为空、已运行的前后端 PID 不变。
- 本机正式数据已追加完整私有备份；隔离测试前后 12 张关键表摘要一致，`quick_check` 正常、0 活动任务，线上回环资源和源码匹配。无外部模型调用。
- 日志和原始 JUnit 保留本机 `backend/.qa-data/desktop-startup-20261024.{log,xml}`；不上传私人日志和数据。
- 独立 Standards：硬违反0、Fowler判断0；独立 Spec：源码确认缺陷0、范围扩张0，并用真实 Windows PowerShell 5.1 运行25项合成正反例通过。文档已按该轴要求补录实际开窗边界。
