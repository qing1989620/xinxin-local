# 学习体验优化：使用效果与边界

本轮从已发布的 `6bbb6f0` 继续检查学习首页、出题工作室和练习页。对照了 zhishi 的页级生成、结构化提交、逐空作答和判分实现，保留 Xinxin 自己的本地数据、授权与任务体系。源码比较见 [zhishi 对照](zhishi-learning-comparison.md)，验收合同见 [本轮需求](specs/2026-10-23-learning-experience.md)。

## 实际使用路径

1. 在学习首页上传或选择资料。单文件上限仍为 256 MiB；识别任务可以刷新恢复，完成后自动更新书架。
2. 打开书本，先检查识别覆盖和原文。数学扫描件可主动选择「先精读当前片段的 3 个原页」，然后调整起止页；预览图片只访问本机，选择原页读取并开始任务才会发送图片。
3. 先总结选中材料，核对学科、知识点、完整原题及实际页段。部分原页的分析始终标注范围；不能把三页摘要当成整本书的总结。
4. 练习册优先使用「原题整理」；理解和迁移练习用「知识拓展」，也可自动组合。数量是上限，原题不足时按尚未入库的完整原题调整计划。
5. 开始练习。多空题逐项填写；切题、切辅导模式和刷新时恢复对应草稿。主观判分失败会保存原作答，显示待核对，并允许稍后重新判分。

## 改动带来的效果

| 场景 | 本轮改进 | 可达到的效果 |
| --- | --- | --- |
| 原片段跨十几页，想先验证资料质量 | 在片段内部选择真实 PDF 起止页，页缓存、预算、重试和复核都使用同一范围 | 可先花较小用量精读三页，再决定是否扩大范围；无效页段在发送前提示 |
| 多选片段后才被总量或页数限制拦住 | 批量选择同时考虑 40 片段、400 题和 60 个不重复原页 | 自动选取本次能处理的一组，范围重叠时前后端页数一致 |
| 想整理 12 题，但只识别出少量完整新原题 | 动态缩小原题计划，已入库原题从下一批候选清单中移除 | 不把换说法的旧原题当新题；没有新原题时明确完成零新增，不刷重复题 |
| 某一批输出截断或失败 | 受限缩批，成功后逐步恢复批量 | 单次失败不再让后续一直只生成一道，仍保留调用上限与部分成功 |
| 最终答案对，解析却有错误 | 先隐藏候选答案和解析独立求解，再对照答案及关键步骤 | 单选结论不一致由程序直接拒绝，解析错误或不能确认时不应入库；比只检查一个正确性标志更可检查 |
| 填空中的区间、分号、符号有含义 | 答案数组逐空提交，保留大小写、括号、小数点及内部空格 | `(0,1)` 不被拆成两空，`1.2` 不会与 `12` 相等；支持分数、有限小数、百分数等精确数值等价 |
| 刷新或切题导致没写完的内容丢失 | 按练习、题目、辅导模式保存本窗口草稿 | 作答和两位辅导的追问各自恢复；成功发送的匹配草稿才会清除，点击讲解不清空未发送的追问 |
| 模型暂时不可用 | 保存待核对结果，并对同一原答案重新判分 | 不把服务异常算成答错，不重复计题；练习完成后仍可重判 |
| 同一道题反复练习，辅导串入旧答案 | 辅导历史与作答绑定当前练习，旧历史单独回看 | 新练习先给切入提示；作答后可主动查看以前的辅导，老师与 Xinxin 仍分开 |
| 测试页面覆盖正在使用的桌面构建 | 浏览器、原生启动测试使用独立前端目录及合成数据 | 测试不会把新界面混到旧后端上，减少点击后出现字段不支持的版本混用问题 |

## 真实模型检查的结论

主人分别授权了本轮最多 12 次、追加最多 4 次 DeepSeek 调用，实际共 16 次。只读取原先失败片段及必要原页，结果保存在忽略目录内的隔离数据库，未修改原书或正式题库。

早期完整链路在第一组三页识别到 9 道原题，计划 3 题并入库 3 题；第二组三页也识别到 9 道原题，计划 3 题、入库 2 题。人工复算发现其中一道虽答案正确，解析却写反了单调性；另发现公式重复转义。不能把这五道都算作质量通过。

随后两次补题请求只返回既有原题，6 个重复候选被拒绝，没有新增。根据这一证据，生成输入改为只提供未入库的原题清单。修正后真实补题计划 2 题，成功新增 2 道不同原题，进入独立解析检查。人工核对其结论及主要证明方法，未发现结论错误；证明的初始情形仍应结合原文逐步检查。

单独加强解析检查提示词仍未让同一模型发现旧解析错误。因此最终改为先盲解、再对照。最后一次真实盲解在不见旧答案和解析的情况下，给出了正确的单调方向及极限。**最终「生成—盲解—对照审题」完整组合通过了合成模型回归，额度内没有再次执行其真实模型全链路**。这一区分是本轮的实际验证边界。

## 仍需知道的限制

- 同一配置模型的多次调用仍可能共享错误，盲解和复核不能证明数学绝对正确。正式备考、证明题与关键答案应对照教材或人工复算。
- 本地填空匹配不做通用计算机代数推理。例如 `x+x` 与 `2x`、不同写法的集合或代码程序，不保证自动识别语义等价；不匹配时要对照参考答案。
- 三页精读只覆盖所选原页。跨页条件、缺图、低清公式、未读页仍可能阻止出题；保留完整题意比补足数量更重要。
- 草稿使用本窗口的会话存储；刷新和切页可恢复，不承诺关闭窗口后、跨设备或存储被禁用后的恢复。退出登录会清理草稿。
- 既有题库、作答和辅导记录被保留，没有自动重做旧题的数学审查，也没有自动重跑主人的失败任务。
- 目前题型为单选、填空和简答；未新增手写识别、任意图形题、公式等价证明或跨设备同步草稿。

## 体验判断

本轮重点让「选什么资料、读了多少、怎样出题、失败怎样继续、结果是否可信」都可见、可恢复。适合先按小页段验证，再逐组建立有出处的练习库；不适合上传整本书后直接把全部生成内容当作标准答案。完整回归、独立审查和未验证项见 [专项审计](ui-audit-learning-experience-2026-10-23/quick-review.md)。

最终自动化验收：后端 413 项、前端单元 70 项、桌面/手机浏览器 133 项、生产资源 2 项通过，另 3 项既定重复场景跳过。两轴独立审查发现均已关闭。本机已经备份并启用新版本，原书、题库、作答和辅导记录数量核对保留；本轮尚未推送 GitHub。已有窗口刷新或重新打开后即可体验。
