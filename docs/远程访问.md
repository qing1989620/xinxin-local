# 手机在外网访问本机后端

局域网方案（手机连同一个 Wi-Fi）已经能用，但它有个硬限制：**手机必须和电脑在同一个网络里**。
要让手机走移动流量、在办公室、在外面也能连到家里这台电脑，就得解决「外网怎么找到你的电脑」这个问题。

## 第一步：先确认你家宽带有没有公网 IP

这一步决定后面能选哪条路，必须先查。

```powershell
tracert -d -h 4 223.5.5.5
```

看第 2 跳的地址：

| 第 2 跳 | 结论 |
| --- | --- |
| `100.64.x.x` 或 `10.x.x.x` 等私有地址 | **CGNAT（运营商级 NAT）**，外网无法主动访问到你 |
| 其他公网地址 | 你可能有真公网 IP，可继续确认 |

另一个更直观的核对：登录路由器管理页看 WAN 口 IP，再在电脑浏览器里搜「IP」看显示的地址。
**两者不一致 → CGNAT**。

本次在本机实测的结果是 CGNAT（第 2 跳为私有地址），所以「直接访问本机 IP」这条路在当前网络下走不通。

## 为什么「给 IP 套一层 SSL」解决不了这个问题

这里有个常见的概念错位：

- **SSL / HTTPS 管的是**：传输加密、防中间人篡改、向客户端证明对端身份。
- **它不管**：外网的数据包怎么路由到你家的路由器。这是 NAT / 路由层的事，跟加不加证书无关。

也就是说，只要运营商在你前面挡了一层 NAT，发往「你的公网 IP」的包根本到不了你家路由器，
你在自己电脑上配什么证书都接不到第一个 SYN。

还有证书这一关，顺便说清楚：

| 证书类型 | 能不能用在你的场景 |
| --- | --- |
| Let's Encrypt 等公共 CA | **只签域名**，不签私有地址；也不签 CGNAT 地址 |
| IP 证书（签公网 IP） | 要求 IP 是真公网且你能证明控制权，多为付费商业证书 |
| 自签证书 | 技术上能用，但手机浏览器会红色告警；App 里信任它会削弱安全性，不推荐 |

**结论：顺序是「先解决寻址，再上 SSL」。** 寻址没解决之前，证书只是锁了一扇没人能敲到的门。

## 三条可行路线

### A. 向运营商申请公网 IP（最治本）

打客服电话（电信 10000 / 联通 10010 / 移动 10086），说明需要公网 IP 用于家庭监控或远程桌面。
不少地区可以免费开通，部分地区需要调整套餐。

开通后能真正做到「电脑就是公网服务器」。要注意：

- 家宽 IP 会变，需要 DDNS 自动更新
- **80 / 443 通常被封**（未备案），改用高位端口，例如 8443
- 备案前不要指望用标准 HTTPS 端口

### B. 内网穿透 / 反向隧道（没有公网 IP 时的正解）

原理是让**本机主动向外**连到一台有公网的机器，外部访问那台机器再回源到本机。
因为是本机主动发起，所以不需要公网 IP，也不需要动路由器。

| 方案 | 地址固定 | 成本 | 适合 |
| --- | --- | --- | --- |
| **frp**（自建，用你的杭州按量实例） | 固定 | 服务器已有 | 长期使用，速度取决于服务器带宽 |
| **Cloudflare Tunnel** | 随机域名会变；绑自有域名则固定 | 免费 | 快速验证，或已把域名托管在 CF |
| **Tailscale** | 固定私有地址 | 免费（个人） | 最安全，不暴露公网 |

### C. 项目自带的 Caddy 网关扮演什么角色

根目录的 `Caddyfile.local` 只负责**本机 / 局域网内的单端口入口**（默认 :8080），
把 `/api`、`/health` 反代到后端、其余走前端静态资源。

它**不能**让外网找到你，但配合上面任意一种穿透方式后可以继续复用：
穿透把公网流量送进来，Caddy 负责内部分发，省一层代理配置。

## 关键一步：CORS 白名单要跟着改

换了访问地址之后，浏览器里的 origin 就变了。如果不在白名单里，会出现：

- 页面能正常打开（静态资源没问题）
- 但 API 请求全部失败（浏览器 CORS 拦截）
- 现象是「界面出来了但一直转圈 / 数据加载不出来」

处理办法：把新的公网地址追加到 `backend/.env` 的 `XINXIN_CORS_ORIGINS`，然后重启后端。

```powershell
# backend/.env
XINXIN_CORS_ORIGINS=https://你的公网地址,http://localhost:8080,capacitor://localhost
```

手机 App（Capacitor）的页面跑在 `https://localhost` 上，不受 CORS 限制；
但如果它去请求**局域网 HTTP** 地址，就是混合内容，需要打包时开启
`VITE_LOCAL_PHONE_TEST=1`（`build-android.ps1 -Local` 会自动处理）。

## 安全提醒

把本机后端暴露到公网，意味着**任何知道地址的人都可以尝试登录你的主人账号**。

建议按这个优先级来：

1. 优先用 **Tailscale** —— 端到端加密，服务不暴露在公网上，攻击面最小
2. 如果用 Cloudflare Tunnel，加上 **Cloudflare Access** 做一层身份验证
3. 账号一定要**强密码**
4. 用不上时**关掉隧道**，需要时再开
