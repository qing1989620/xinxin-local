# 手机在外网访问本机后端

局域网方案（手机连同一个 Wi-Fi）只覆盖「同一网络」。要让手机走移动流量、在别的城市也能连回这台电脑，需要解决「外网怎么找到你的电脑」。

## 先搞清楚：你家宽带有没有公网 IP

这一步决定能走哪条路，必须先查。

```powershell
tracert -d -h 4 223.5.5.5
```

看第 2 跳：

| 第 2 跳 | 结论 |
| --- | --- |
| `100.64.x.x` 或 `10.x.x.x` 等私有地址 | **CGNAT（运营商级 NAT）**，外网无法主动访问到你 |
| 其他公网地址 | 有可能有真公网 IP，继续确认 |

另一个核对办法：登录路由器管理页看 WAN 口 IP，再在电脑浏览器里搜「IP」看显示的地址。两者不一致 → CGNAT。

本机实测（湖南，WLAN）：

```
1  10.3.255.254      ← 路由器
2  10.1.2.2          ← 运营商 NAT（私有地址 = CGNAT）
3  116.128.229.129   ← 共用公网出口
```

结论：**没有真公网 IP，且无全局 IPv6**。所以「直接访问本机 IP」这条路在当前网络下物理上行不通。

## 为什么「给 IP 套一层 SSL」解决不了

概念上有错位：

- **SSL / HTTPS 管**：传输加密、防中间人篡改、向客户端证明对端身份
- **它不管**：外网的数据包怎么路由到你家路由器（这是 NAT / 路由层的事）

CGNAT 下，发往「你的公网 IP」的包根本到不了你家路由器，你在自己电脑上配什么证书都接不到第一个连接。

再看证书这一关：

| 证书类型 | 能否用于你的场景 |
| --- | --- |
| Let's Encrypt 等公共 CA | **只签域名**，不签私有地址，也不签 CGNAT 地址 |
| IP 证书（签公网 IP） | 要求 IP 是真公网且能证明控制权，多为付费商业证书 |
| 自签证书 | 技术可行，但手机浏览器红色告警；App 里信任它会削弱安全性，不推荐 |

**正确顺序：先解决寻址，再上 SSL。** 寻址没解决前，证书只是锁了一扇没人能敲到的门。

## 实测记录：云隧道方案已验证可行

已在本机完成云隧道的握手与回源验证：

- 出网健康检查全部通过（DNS 解析、QUIC/UDP、HTTP/2 TCP、控制面 API）
- 隧道成功注册：`Registered tunnel connection ... protocol=quic`
- 分配公网 HTTPS 地址，回源 `GET /health` 返回 `200`，响应体
  `{"status":"ok","product":"Xinxin","version":"0.1.0"}`

也就是说：**不需要公网 IP、不需要路由器端口映射，手机从外网可以直接访问本机后端。** 隧道由本机主动向外发起，因此 Windows 防火墙的入站拦截不影响它。

## 怎么用

最省事的方式：双击根目录的 **`启动公网访问.cmd`**。它会先拉起本机三个服务，
再打开隧道，最后把公网地址打印出来。

等价的手动命令：

```powershell
./Start-Xinxin-Local.ps1 -NoBrowser   # 本机后端 + 前端 + 网关
./Start-Tunnel.ps1                    # 打通公网入口
```

脚本会：检查 8080 是否在监听 → 启动隧道 → 抓取并打印公网 HTTPS 地址 →
把该地址自动写进 `backend/.env` 的 `XINXIN_CORS_ORIGINS` → 重启本机三个服务让 CORS 生效，
并把地址存到 `.runtime/public-url.txt`。

打印出来的地址直接给手机浏览器或 App 用即可，**不需要连同一个 Wi-Fi**。

关闭公网入口：

```powershell
./Stop-Tunnel.ps1          # 只关隧道
./Stop-Tunnel.ps1 -All     # 隧道 + 后端/前端/网关 一起停
```

### 排障：API 能通、页面却 403

这是 Vite 7 的 Host 校验：静态页面被拦，而 `/api` 走代理不受影响。
`frontend/vite.config.ts` 已放行隧道域名族：

```ts
allowedHosts: [".trycloudflare.com", ".zhixuedu.cn", ".localhost"]
```

换用其他隧道/域名时，把后缀加进 `server.allowedHosts` 与 `preview.allowedHosts` 即可。

### 关于地址会变

免费随机隧道每次启动地址都会变。脚本会在每次启动时自动同步 CORS，
但手机端保存的地址也需要同步更新（App 设置页可改，或使用打印出的新地址）。

如果需要**长期固定地址**，两个方向：

1. **frp 自建中转**：用你自己的公网服务器（杭州按量实例即可）跑 `frps`，
   本机跑 `frpc`，地址由你自己的域名或服务器 IP 决定，固定不变，速度取决于服务器带宽。
2. **云厂商命名隧道**：绑定自有域名，需要把域名的 DNS 托管到对应服务商。

## 换地址后必须做的事：CORS 白名单

浏览器里的 origin 变了，如果不在白名单里，会出现：

- 页面能打开（静态资源正常）
- API 请求全部失败（浏览器 CORS 拦截）
- 现象是「界面出来了但一直转圈 / 数据加载不出来」

`Start-Tunnel.ps1` 已经自动处理。手动配置的格式：

```dotenv
XINXIN_CORS_ORIGINS=https://你的公网地址,http://localhost:8080,capacitor://localhost
```

改完必须重启后端才生效。

手机 App（Capacitor）页面跑在 `https://localhost`，不受 CORS 限制；
但它去请求**局域网 HTTP** 地址属于混合内容，需要打包时带
`VITE_LOCAL_PHONE_TEST=1`（`build-android.ps1 -Local` 会自动处理）。

## 安全提醒

把本机后端暴露到公网，等于**任何知道地址的人都能尝试登录你的主人账号**。

优先级建议：

1. 优先用组网型方案：**端到端加密，服务不暴露在公网**，攻击面最小
2. 若用云隧道，在前面加一层身份验证（如 Access 类服务）
3. 账号必须**强密码**
4. 不用时**关掉隧道**，需要再开
