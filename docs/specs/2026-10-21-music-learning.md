# 音乐与学习优化需求

基线：`0ad684cb8795b3d9f821ef9e5eeecdeeb4f8084f`（实施前已从 GitHub 拉取并阅读 main README）。

来源：主人 2026-10-21 在本会话提出的优化、修复和测试后推送要求。

1. 歌曲列表在鼠标触碰时轻微向右移动，停留时保持稳定；播放进度刷新、情绪校准、收藏等更新不能重建列表或丢失键盘焦点。减少动态效果模式下禁用位移动画。
2. 音乐对 Xinxin 的影响可在轻微、自然、明显、沉浸四档调节，默认自然，可关闭；档位保存到后端，Agent 与 Xinxin 辅导都使用选定档位。保留音乐情绪衰减、关闭与清空行为。性格、互动、语气随档位变化，事实、解题准确性和执行权限不随音乐变化。
3. 学习讲题可选择普通老师或 Xinxin 辅导；前者专注清晰讲解，后者保留已有 Xinxin 性格并结合音乐氛围，让练习更有趣。两者都讲步骤、支持追问和函数图，各自按题保存历史；旧历史迁移为普通老师。
4. 修复相关流程中的可复现问题：异步响应串题或串搜索、重复提交、失败留下假对话、未作答题目的参考答案暴露，以及练完后无法再讲错题、重新练习丢失章节范围。
5. 保留现有页面设计、本地数据与密钥保护、前后端 HTTP 边界及旧接口默认行为。测试使用独立合成数据，不读取私人聊天或更改主人运行中的数据库。
6. 执行后端与前端全套现有测试、针对新增行为的回归、类型检查、生产构建与桌面/手机视口浏览器验证；记录证据与无法验证的外部服务范围。通过后提交并推送 GitHub。

审查：前端按 BadGoods review-frontend-production 的 quick 实施流程检查音乐和学习旅程，并运行全站冒烟；后端按 mattpocock code-review 分别执行 Standards / Spec 独立审查。此范围不声称穷举全部输入或保证没有缺陷。
