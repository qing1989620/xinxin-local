## Standards

初查 1 项 P2：新的事务直接绑定字符串，绕过原 Store.execute 的 Unicode 清理。合成模型返回落单 UTF-16 代理项时 SQLite 抛 UnicodeEncodeError，题目和进度一起回滚。修复输出字段清理与 encode 序列化，复核再次查出填空答案嵌套数组的漏点，已改用 encode(answer)。回归包含短答、填空、讲解、判分理由、领域调用标题与学生答案；HTTP 边界本身拒绝无效代理项也单独验证。

最终独立复核：该 P2 关闭，未发现其他未解决的 Standards 可行动问题。检查了鉴权、跨书来源、创建 / 删除串行与事务、取消后的迟到响应、补出范围、幂等、预算、历史恢复和 PDF 页序匹配。

## Spec

初查 2 项 P2，均经独立复核关闭：

1. 恢复已结束任务时，其他请求可能仍是生成前的空题库快照。终态恢复现在同步刷新书本、题库和来源；浏览器用例刻意先返回旧资源，再恢复完成任务，验证题库和练习按钮最终一致。
2. 相邻原文快速导航可能被旧响应覆盖。现在取消旧导航请求、丢弃取消响应，并在对话框卸载时清理；用延迟的“下一段”响应与更快的“上一段”响应验证最后一次选择保留。

其余已检查的完整来源、可靠 PDF 页序、质量校验、预算、取消 / 中断 / 补出和最新错题逻辑未发现合同阻断项；未见明显范围扩张。审查者查看了桌面与手机截图，未自行宣称真实模型或真实 iOS 通过。

## 桌面入口实际复验

学习更新推送后，用原桌面 Xinxin 快捷方式发现另一条真实启动路径问题：Windows PowerShell 5.1 在桌面调用者 `*>>` 捕获日志时，把 Vite 写到 stderr 的非致命构建警告当作异常，提前中断了服务版本更新。独立启动脚本的既有测试没有覆盖这一重定向上下文。

补丁 `51786b8` 给依赖安装和构建增加受控原生命令调用：局部处理 stderr 为可保留的日志，真实非零退出仍然失败，并在 finally 还原错误偏好和控制台编码。启动失败时也保留子脚本日志，错误模板和日志明确按 UTF-8 读取；启动成功后关闭本应用专用临时 profile 的旧错误窗口。

新增两项实际 PowerShell 5.1 测试覆盖 warning + exit 0 成功、exit 7 失败、调用者状态恢复，以及中文模板 / 诊断日志无乱码；与原有启动更新、进程归属和编码检查最终 **6 passed，30.48 秒**。复核又指出既有日志轮转读取未指定 UTF-8，已修复，并补无 BOM 中文日志两次轮转的回归；原生命令 / 中文诊断 / 轮转与编码检查 **5 passed，1.20 秒**。实际将前端产物标为过期，通过原快捷方式触发完整 npm / Vite / PWA 构建，警告保留且正常进入服务验证。主人数据库更新前已在本地私人数据目录做一致性备份，没有读取或外发内容。

本机最终实测：网关健康、后端源码指纹相符、桌面前端缓存版本相符，专用应用窗口 1 个，临时错误窗口 0 个。启动器补丁也通过独立 Standards / Spec 复核；应用代码未因这次脚本修复发生变化。
